01 / 我们的目标
短期贯穿工程流程 · 长期学习工具能力

让模型
学会做 OPC。

从调用 EDA 完成任务，
走向模型自身掌握更多优化与计算能力。

OPC：提前修正掩模，让曝光后的图形更接近设计。

OPTICAL PROXIMITY CORRECTION 流程示意
目标 Target希望印成什么样
掩模 Mask实际修改的图形
仿真 Print预计会印成什么样
改掩模 → 做仿真 → 对比目标非实测图
短期：通过 Agentic 方式贯穿流程模拟工程师的执行过程：接收任务、选择工具、调用 EDA、调参数、看仿真，根据反馈持续迭代，直到满足验收要求。
长期：把部分工具能力学进模型探索让模型直接生成或修正掩模、预测仿真结果、学习优化策略，逐步内化 EDA 的部分计算与优化能力，减少对外部工具的依赖。
重点：让模型完成一项有结果、有检查的工程任务01 / 09
02 / 模型怎么做事

想一步，做一步，看结果，再调整。

短期先让模型贯穿工程流程：接收任务与环境，调用 EDA 工具，根据反馈反复调整，直到达标或确认未完成。

人工操作

工程师 → EDA 工具 → 看结果，再手动调整

Agent 方式

工程师定目标 → Agent → OPC / 仿真 / 检查工具 → 结果反馈给 Agent ↺

ReAct 就是下面这个循环：判断 → 调用工具 → 看结果 → 再判断。

仿真里的线头比目标短。先判断：是线端补偿不足，还是邻近图形的影响没有处理好？

OPC 软件完成数值计算；模型负责选工具、设配方、判断下一步。这些决策依赖训练中学到的能力，以及当前任务里的资料和工具反馈。
工具提供计算与反馈，模型需要学会选择操作、理解结果，再决定下一步。

03 / 模型的能力从哪里来

模型通过训练，
从数据中学习如何做事。

为了让模型掌握 OPC 中的判断与操作，我们需要把完整执行过程组织成训练数据：当时的任务和环境、采取的行动、收到的反馈，以及最终结果。

01 / 任务

要达到什么

输入图形、目标指标、允许花多少次尝试。

02 / 环境

能用什么

工艺模型、图层、软件、可调参数和运行限制。

03 / 过程

具体怎么做

模型发出的消息、工具调用、参数和真实返回结果。

04 / 结果

到底好不好

最终掩模、仿真图形、指标和独立验收结论。

训练学习有效决策与失败后的修正评测用未见任务检验是否学会补数据针对暴露的短板补充案例
模型在训练时从执行记录中学习决策；执行新任务时，运用学到的能力，根据当前反馈继续判断和行动。

04 / 数据构造的三个要求

贴近实际、覆盖广，
质量贯穿全过程。

目前没有真实工业任务数据和工程师反馈。我们基于开源版图、论文与工具文档构造（mock）任务和环境，尽量符合物理规律与 OPC 专业常识，并通过多样性覆盖更多接近真实的场景。

01

真实性

任务与环境尽量贴近实际工程。
输入、工具、工艺条件、操作与目标应符合物理规律和专业常识。

依据开源资料检查工艺与工具的适用性，明确 mock 场景的假设；用软件实跑检查，尽量贴近真实场景。

02

多样性

覆盖不同环境、任务和执行方式。
组合不同图形、工艺、工具、约束和问题类型。

在物理和工程上合理的范围内扩展场景，避免重复相似案例，弥补真实场景覆盖不足。

全程

质量

任务质量、执行质量、结果质量。
从任务设计到模型执行，再到结果验收，每一步都有检查要求。

任务：目标清楚、条件一致、可执行。
执行：调用有效、反馈真实、记录完整。
结果：独立验收，成功与失败都有依据。

真实性与多样性指导场景设计；质量要求贯穿任务、执行与验收04 / 09
05 / 任务与环境的多样性

让模型在不同任务条件下，
都能完成 OPC。

多样性覆盖任务与环境，也覆盖执行时采取的策略、遇到的反馈和失败后的处理方式。

图形不同

线头、拐角、孔阵列、疏密交界

图层不同

poly、metal、via 等；逐一确认适用性

工艺不同

光源、材料、曝光与焦距条件

工具不同

Calibre、Synopsys Proteus、开源 OpenILT 等

任务不同

减小边缘误差、修缺陷、提高稳定性

约束不同

参数范围、尝试次数、运行时间

执行不同

调整参数、比较方案、定位报错、失败恢复

反馈不同

有效改善、没有改善、规则违规、运行失败

线头缩短，怎么补回来？

换不同线距与拐角结构，要求减小边缘误差，同时避免相邻线桥连。

任务设计示例；具体组合通过软件和工艺适用检查后才使用。
先按类别分配 → 再检查组合能否运行 → 最后统计实际覆盖。缺哪一类，就补哪一类。

不同工具的接口、能力和适用条件需要分别确认；同一材料调整光学参数，也不等于多个独立校准的工艺。

06 / 管线如何落实多样性

把多样性落实到
任务构造、执行与验收。

当前管线已把任务包、EDA 调用和执行记录串起来。接下来，按下面三个环节扩充场景、统计覆盖，并持续补强真实性与质量检查。

环节真实性多样性质量
任务与环境基于开源版图、论文与工具文档 mock 任务包和流程，尽量符合物理规律与专业常识，贴近真实场景。扩充图形、图层、工具、工艺条件和任务目标，控制同源案例重复。检查输入完整、目标一致、工艺与工具适用，先确认任务可执行。
模型执行以真实 EDA 返回为反馈；参考公开文档和案例构造操作步骤与问题定位过程。覆盖不同调整策略，以及报错、无改善、违规后的恢复过程。核对消息、工具调用、返回结果和预算；保留可追溯的候选记录。
验收与数据参考公开资料设定检查项，用软件输出核验；明确研究模型和 mock 场景的假设与适用边界。覆盖不同难度、失败类型及验收目标，按薄弱类别补充数据。独立核对最终掩模和指标；标清失败原因，隔离训练与测试同源数据。
先按类别设计任务 → 检查工艺与工具是否适用 → 执行并保存记录 → 统计覆盖，针对缺口补充场景。

07 / 一个 nmOPC 失败案例

XOR 降低了，
但这个候选仍未通过检查。

opc-0207：固定目标图形、工艺模型和评分区域，调整 recipe 后 XOR 减小，但 MRC 违规从 2 处增加到 6 处，候选未通过物理约束检查。

  1. 读取任务包

    GDS、评分窗口与周围图形、初始 SVRF recipe、工艺模型、工具及目标。

  2. 运行并测量基线

    调用 nmOPC 生成掩模，用 OPCverify 仿真，记录初始 XOR 和违规数。

  3. 根据反馈修改参数

    分段最小长度保持 0.02 µm；每次迭代最大移动量从 0.003 调到 0.007 µm，运行候选并保存掩模与仿真轮廓。

  4. 识别失败，保留证据

    XOR 虽然下降，但 MRC 违规增加。将该候选标记为约束未通过，保留参数、检查结果与执行记录。

XOR 为评分框内目标与仿真图形不重合的面积 / 评分框面积。使用未校准研究工艺模型；图为软件仿真，非晶圆实测。本例说明软件执行成功和 XOR 改善，仍可能无法通过验收。

08 / 方案一：手册与内部知识库增强

让模型理解资料，
并学会解决工程问题。

高质量轨迹直接用于训练；对于需要增强的部分，先通过基础 QA 内化知识，再用失败或未完成的 trace 构造工程修复任务。

01 / 基础 QA

理解手册，
内化部分通识知识

数据输入：手册原文、example、图文和内部知识库资料，不局限于 OPC 手册。

训练内容：解释语法、适用条件、默认值、限制与例外，区分原文事实、推断和信息不足，让模型通过训练掌握这些知识。

验收：解释正确、条件完整，引用能够支持结论。
02 / 工程问题修复

检索资料，
修复报错或流程阻塞

数据输入：截取失败或未完成的 trace，提供当前 recipe、日志及产物。

执行过程：自主检索手册和 example，定位阻塞原因，修改 recipe 并实际验证；保留检索、判断、修复和检查的完整过程。

验收：原问题解除、修改范围合理，且没有引入回归。
基础 QA 帮助模型理解知识；工程修复任务让模型学会把知识应用到具体问题。

09 / 方案二：Agent 优化能力增强

流程能运行之后，
让 Agent 找到更有效的优化路径。

针对语法正确、工具运行完成，但最终指标或约束未达标的 case，提供 recipe、版图上下文、日志、产物和历史实验，让 Agent 定位问题、调整 recipe 并验证。

01 / 定位问题

热点可能和哪段 recipe 有关

结合热点位置、误差分布和违规信息，找出相关参数或规则，提出可能原因，再通过实验确认。

02 / 对比实验

不同 recipe 会带来什么影响

固定版图、工艺模型、工具版本和评价标准，在允许的修改范围与预算内，选择有针对性的 recipe 运行对比。记录哪些修改有效、影响哪些位置、是否新增违规，让模型学会更有效的优化方向。

03 / Skill 辅助执行

用执行指导提高效果，再通过训练内化方法

将问题诊断步骤、recipe 调整方法、实验设计经验和检查清单整理成 Skill，提供给模型辅助执行。记录模型使用这些指导解决问题的过程，将高质量轨迹用于训练，让模型逐步学会这些方法，提高后续任务的执行效果。

对应前面的 opc-0207：XOR 下降但 MRC 违规增加。重点是定位相关 recipe 与违规之间的关系，验证调整能否兼顾优化目标和约束。
增强目标：从理解知识、修复工程问题，进一步学会诊断、实验搜索与端到端达标优化09 / 09
