01 / 我们的目标
短期贯穿工程流程 · 长期学习工具能力

让模型
学会做 OPC。

从调用 EDA 完成任务，
走向模型自身掌握更多优化与计算能力。

OPC：提前修正掩模，让曝光后的图形更接近设计。

OPTICAL PROXIMITY CORRECTION 流程示意
目标 Target希望印成什么样
掩模 Mask实际修改的图形
仿真 Print预计会印成什么样
改掩模 → 做仿真 → 对比目标非实测图
短期：通过 Agentic 方式贯穿流程模拟工程师的执行过程：接收任务、选择工具、调用 EDA、调参数、看仿真，根据反馈持续迭代，直到满足验收要求。
长期：把部分工具能力学进模型探索让模型直接生成或修正掩模、预测仿真结果、学习优化策略，逐步内化 EDA 的部分计算与优化能力，减少对外部工具的依赖。
重点：让模型完成一项有结果、有检查的工程任务01 / 07
02 / 模型怎么做事

想一步，做一步，看结果，再调整。

工程师给出目标，Agent 调用工具完成任务，并根据反馈继续调整。

人工操作

工程师 → EDA 工具 → 看结果，再手动调整

Agent 方式

工程师定目标 → Agent → OPC / 仿真 / 检查工具 → 结果反馈给 Agent ↺

ReAct 就是下面这个循环：判断 → 调用工具 → 看结果 → 再判断。

仿真里的线头比目标短。先判断：是线端补偿不足，还是邻近图形的影响没有处理好？

OPC 软件完成数值计算；模型负责选工具、设配方、判断下一步。这些决策依赖训练中学到的能力，以及当前任务里的资料和工具反馈。
怎样让模型更会判断和行动？把真实的任务、操作、反馈和结果变成训练数据，让模型学会如何推进这个循环。

03 / 模型的能力从哪里来

模型通过训练，
从数据中学习如何做事。

模型通过训练，学习在什么条件下选择什么操作、怎样理解工具反馈，以及何时调整方案。为此，每条训练数据需要包含任务、环境、执行过程和结果。

01 / 任务

要达到什么

输入图形、目标指标、允许花多少次尝试。

02 / 环境

能用什么

工艺模型、图层、软件、可调参数和运行限制。

03 / 过程

具体怎么做

模型发出的消息、工具调用、参数和真实返回结果。

04 / 结果

到底好不好

最终掩模、仿真图形、指标和独立验收结论。

训练学习有效决策与失败后的修正评测用未见任务检验是否学会补数据针对暴露的短板补充案例
模型在训练时从执行记录中学习决策；执行新任务时，运用学到的能力，根据当前反馈继续判断和行动。
执行记录经过核验和筛选，再用于训练；一次工具反馈不等于模型参数已更新03 / 07
04 / 数据的三个标准

做得对、覆盖广、贴近实际。

目前难以获得足够的真实工业数据。我们尽量构造更多符合物理规律和 OPC 专业常识的场景，用多样性弥补真实场景覆盖不足。

01

质量

要求清楚，结果可靠。
有明确目标、有最终提交，也能重新检查。

不只看误差变小：还要看有没有桥连、断线、缺孔，是否满足掩模规则和预算。

02

多样性

换图形，也换问题。
覆盖不同工艺、工具、难度和失败原因。

在物理和工程上合理的范围内组合条件，覆盖不同问题及处理方式，避免只重复相似案例。

03

真实性

场景合理，执行记录可信。
尽量贴近工程流程；指标来自软件实跑，消息、调用与结果能对得上。

构造场景需要核查物理与工具适用性；保留原始输出并独立验收，后续用工业案例校正场景设计。

多样性用于弥补场景覆盖不足；每个场景仍需满足物理合理性和记录真实性04 / 07
05 / 任务与环境的多样性

让模型在不同任务条件下，
都能完成 OPC。

图形不同

线头、拐角、孔阵列、疏密交界

图层不同

poly、metal、via 等；逐一确认适用性

工艺不同

光源、材料、曝光与焦距条件

工具不同

Calibre、Synopsys Proteus、开源 OpenILT 等

任务不同

减小边缘误差、修缺陷、提高稳定性

约束不同

参数范围、尝试次数、运行时间

线头缩短，怎么补回来？

换不同线距与拐角结构，要求减小边缘误差，同时避免相邻线桥连。

任务设计示例；具体组合通过软件和工艺适用检查后才使用。
先按类别分配 → 再检查组合能否运行 → 最后统计实际覆盖。缺哪一类，就补哪一类。

不同工具的接口、能力和适用条件需要分别确认；同一材料调整光学参数，也不等于多个独立校准的工艺。

这些任务用于收集执行记录，下一步将记录用于训练与评测05 / 07
06 / 模型如何持续进步

用多样的任务训练，
用没见过的任务检验。

前面定义了数据的标准和任务的多样性。接下来，让模型在这些任务中执行，核验执行记录，再将合格记录用于训练，并在新任务上检查效果。

01 / 收集过程

在不同任务中执行

让模型读取任务、调用软件、根据反馈调整。保留完整执行记录，用独立检查确认结果，筛选有效操作和失败后的修正。

02 / 用于训练

从执行记录中学习

用合格记录训练模型，学习工具调用和决策；也可以用可验证的任务结果作为奖励，进一步优化行动选择。

03 / 检验提升

在新任务上比较效果

在相同工具、预算和验收标准下，对比训练前后的模型。同源设计分组隔离，检查模型能否处理未见过的图形和任务条件。

模型进步了吗？

任务达标率是否提高 · 同样预算下结果是否更好 · 工具调用出错是否更少 · 失败后能否恢复

根据评测发现短板 → 补充相应任务和记录 → 再训练、再检验06 / 07
07 / 现在在做什么

先把数据管线做扎实，
再用它验证模型能否进步。

已有基础，正在补强

01已有 1,000 条历史任务及运行记录，保留原始版本。

02已验证三条 Calibre 路线的部分真实运行。

03正在补齐适用检查、预算、消息与结果对应、独立验收。

接下来怎么推进

01先解决环境稳定性和软件、工艺的适用问题。

02再做小批完整运行，检查数据是否可信、够多样。

03用合格数据训练，并在未见过的任务上检验提升。

让模型从“知道 OPC 是什么”，
走到“能把一个 OPC 任务做完、做好”。

已有任务不等于全部达标；当前仍有掩模规则未通过、改进效果不确定的控制案例。尚未证明训练后的能力提升，也不声称达到工厂签核水平。

当前优先优化管线，暂不新增任务或运行模型 trace07 / 07
